## 파일명 규칙

- 콘텐츠의 한글 제목을 추출하거나, 영어 제목을 자연스러운 한국어로 번역.
- 금지 문자 제거: `/`, `\`, `:`, `?`, `*`, `"`, `<`, `>`, `|`
- 연속 공백 → 단일 공백
- 최대 120자
- 확장자 `.md`
- 중복 시 ` (2)`, ` (3)` 접미사

예시(실제 파일):
- `AGENTS.md가 에이전트 평가에서 Skills보다 우수한 성능을 보임.md`
- `Claude Code 마스터 가이드 - 설정 완전 정리.md`
- `임베딩 없는 시맨틱 검색 - Semantic Search Without Embeddings.md`

## Frontmatter

필드 순서 고정. 빈 값 허용은 아래 표 참조.

```yaml
---
source_url: https://news.hada.io/topic?id=26262
created: 2026-04-17T16:52:00
modified: 2026-04-17T16:52:00
title: 제목 (파일명과 동일하되 확장자 제외)
tags:
summary:
---
```

| 필드 | 타입 | 빈 값 | 설명 |
|---|---|:---:|---|
| `source_url` | string | ❌ | 원본 URL. http(s)로 시작. |
| `created` | ISO-8601 (no tz) | ❌ | `date '+%Y-%m-%dT%H:%M:%S'` 결과. |
| `modified` | ISO-8601 (no tz) | ❌ | 최초 생성 시 `created`와 동일. |
| `title` | string | ❌ | 파일명 본문과 동일. |
| `tags` | 빈 or list | ✅ | 기존 파일 다수가 빈 값. 의미 있는 태그 있으면 YAML list. |
| `summary` | 빈 or string | ✅ | 1-2문장 한국어 요약. 빈 값 허용. |

### YAML 안전 처리

`title`이 아래 중 하나라도 포함하면 따옴표로 감싼다:
- 콜론 `:`
- 샵 `#`
- 앞/뒤 공백
- 앞에 `-` (리스트 오인)
- 작은따옴표 `'` (작은따옴표 스칼라 대신 큰따옴표 스칼라 + 이스케이프)

예: `title: "Python: 3.12 신기능 정리"` (콜론 포함)

### 시각 획득

**반드시** 현재 로컬 시간을 ISO-8601 형식(`YYYY-MM-DDTHH:MM:SS`, 타임존 없음)으로 사용. 임의 생성 금지. Linux: `date '+%Y-%m-%dT%H:%M:%S'`, Python: `datetime.now().strftime('%Y-%m-%dT%H:%M:%S')`.

## 본문 관용

기존 Resource 파일들의 **공통 고정 3요소**와 **가변 섹션**:

### 공통 고정 3요소

순서 그대로 유지.

```markdown
# {title}

> 출처: {source_url}

## 개요

{2-4줄. 이 콘텐츠의 주제와 핵심 요점.}
```

### 가변 섹션

`## 개요` 이후는 콘텐츠에 맞춰 **자유롭게** `##` 섹션을 사용한다. 리터럴 `## 핵심 내용`을 강제하지 않는다. 실제 레포 관용 예:

- `## 배경` / `## 문제` — 기술/정책/사회 이슈
- `## 핵심 기능` / `## 핵심 논지` / `## 핵심 구성 요소` — 제품/논문 요약
- `## 기술 스택` / `## 빠른 시작` — 소프트웨어 소개
- `## 지원 컴포넌트` / `## 적용 대상` — 프레임워크/라이브러리
- `## 시사점` / `## 결론` / `## 정리` — 의견·분석
- `## 참고` / `## 커뮤니티 반응` / `## 참고 링크` — 원문 인용 링크, 반응

섹션 수는 콘텐츠에 비례. 짧은 기사: 3-4개 (`## 개요` + 1-2개 내용 + `## 참고`). 긴 가이드: 5-7개.

### 작성 톤

- 3인칭 서술. 한국어 관용 어투.
- **추측 금지** (`~인 것 같다`, `아마도`). 원문에 없는 내용은 쓰지 말 것.
- 원문이 영어여도 본문은 기본 한국어. 전문용어는 영어 병기 허용 (`Skills(스킬)`).
- 불릿/문단 균형. 과도한 불릿 금지.

## 섹션 선택 가이드

| 콘텐츠 유형 | 권장 섹션 |
|---|---|
| 기술 뉴스/논평 | `## 개요` → `## 배경` → `## 시사점` |
| 오픈소스 소개 | `## 개요` → `## 핵심 기능` (서브섹션 `###`) → `## 기술 스택` → `## 빠른 시작` |
| 연구/논문 요약 | `## 개요` → `## 문제 배경` → `## 핵심 논지` → `## 결론` |
| YouTube 영상 | `## 개요` → `## 주요 내용` (챕터별 `###`) → `## 참고` |
| 튜토리얼 | `## 개요` → `## 준비물` → `## 단계별 절차` → `## 트러블슈팅` |
| 접근 불가 / placeholder | `# {title}` + `> 출처:` + `## 참고` 한 섹션만 |

## 소스 유형별 변형

### 일반 블로그 / 뉴스 / 기술 문서

위 본문 관용 그대로. `## 개요` 이후 콘텐츠에 맞는 섹션.

### YouTube

```markdown
# {영상 제목}

> 출처: https://www.youtube.com/watch?v=...

## 개요

{영상 설명 기반 2-4줄 요약}

## 주요 내용

### {챕터 1 제목 또는 주제}

{내용}

### {챕터 2}

{내용}

## 참고

- 채널: {channel_name}
- 길이: {duration}
```

### X/Twitter (fetch 실패 시)

웹 스크래핑 차단으로 본문 확보 실패가 흔하다. 이 경우 최소한의 placeholder:

```markdown
# {URL에서 추정한 제목 또는 "X 포스트"}

> 출처: {x_url}

## 참고

- X(구 Twitter)는 직접 스크래핑이 차단되어 본문을 확보하지 못함.
- 필요 시 사용자가 트윗 본문을 직접 보충할 것.
```

반드시 최종 보고에서 **보충 필요 / 제출 불가** 목록에 추가.

### Threads

YouTube와 동일 패턴. 출처에 작성자/계정 기재.

### 접근 불가 (404, 페이월, 삭제된 글)

실제 레포 관용(`GeekNews - 삭제된 글 (id 26145).md`)을 따라 **최소 노트**:

```markdown
---
source_url: {url}
created: {now}
modified: {now}
title: {title}
tags:
summary:
---
# {title}

> 출처: {url}

## 참고

- {구체 상태: "404 Not Found", "유료 구독 전용 페이월", "삭제됨" 등}
- {사이트/소스에 대한 간단한 맥락 1-2줄}
```

HoneyCombo 제출 **불가** 플래그.

## 실전 예시

### 예시 1: GeekNews 기사 (기본)

```markdown
---
source_url: https://news.hada.io/topic?id=26262
created: 2026-04-17T16:52:00
modified: 2026-04-17T16:52:00
title: AGENTS.md가 에이전트 평가에서 Skills보다 우수한 성능을 보임
tags:
summary:
---
# AGENTS.md가 에이전트 평가에서 Skills보다 우수한 성능을 보임

> 출처: https://news.hada.io/topic?id=26262

## 개요

Vercel 블로그가 발표한 실험으로, Next.js 16 API 대상 평가에서 프로젝트 루트의 `AGENTS.md` 문서 인덱스가 Skills 기반 접근보다 높은 정확도를 기록했다.

## 문제 배경

- AI 코딩 에이전트는 훈련 데이터가 구버전 API에 기반함
- Next.js 16의 `'use cache'`, `connection()`, `forbidden()` 등은 학습 데이터에 없음

## 실험 결과

### Skills 접근법

- 필요 시 에이전트가 호출
- 56%에서 Skill 미호출, 기본 통과율 53%

### AGENTS.md 접근법

- 프로젝트 루트 단일 문서
- 기본 통과율 70% 개선

## 시사점

"찾아야 하는" Skills보다 "항상 보이는" AGENTS.md 쪽이 실질 성능이 높다.
```

## 검증 체크리스트

생성된 파일마다 확인:

- [ ] 맨 앞 `---` 라인으로 frontmatter 시작, 닫는 `---` 직후 빈 줄 1개
- [ ] frontmatter 6개 필드 순서: `source_url`, `created`, `modified`, `title`, `tags`, `summary`
- [ ] `title`이 YAML-sensitive 문자 포함 시 따옴표 처리
- [ ] `# {title}` H1 단 하나, 파일 최상단 (frontmatter 뒤)
- [ ] `> 출처: {source_url}` blockquote 존재
- [ ] `## 개요` 섹션 존재 (placeholder 케이스 제외)
- [ ] 본문에 추측성 표현 없음
- [ ] 파일명이 `# {title}`과 일치 (확장자 제외)
