# Writing Standards

### The Golden Rule

**This is not Wikipedia about the thing. This is about the thing's role in the subject's life.**

A page about a book isn't a book review. It's about what that book meant to the person, when they read it, and what it changed.

### Tone: Wikipedia, Not AI

Write like Wikipedia. Flat, factual, encyclopedic. State what happened. The article stays neutral. Direct quotes from entries carry the emotional weight.

**Never use:**

- Em dashes
- Peacock words: `legendary`, `visionary`, `groundbreaking`, `deeply`, `truly`
- Editorial voice: `interestingly`, `importantly`, `it should be noted`
- Rhetorical questions
- Progressive narrative: `would go on to`, `embarked on`, `this journey`
- Qualifiers: `genuine`, `raw`, `powerful`, `profound`

**Do:**

- Lead with the subject and state facts plainly
- One claim per sentence. Short sentences.
- Use simple past or simple present tense
- Prefer attribution over assertion: `He described it as energizing` not `It was energizing`
- Let facts imply significance
- Replace adjectives with dates and specifics

**One exception:** direct quotes carry the voice. The article is neutral. The quotes do the feeling.

### Frontmatter Schema

| Field | Type | Required | Description |
|---|---|:-:|---|
| `title` | string | ✓ | Human-readable article title |
| `type` | enum | ✓ | One of: person, project, place, concept, event, era, transition, decision, philosophy, pattern, tool, company, institution, book, film, music, experiment, setback, relationship, mentorship, community, strategy, technique, skill, idea, artifact, restaurant, health, media, routine, metaphor, assessment, touchstone |
| `created` | date | ✓ | ISO 8601 date when the article was written |
| `last_updated` | date | ✓ | ISO 8601 date of most recent edit |
| `aliases` | list[str] | ✓ | Must include filename stem, plain title, and alternatives |
| `related` | list[str] | ✗ | Cross-references to other articles using wikilinks |
| `sources` | list[str] | ✓ | 12-hex entry IDs cited by the article |
| `batch` | string | ✗ | Optional batch ID for lineage and debugging |

Invalid frontmatter is a lint error for new articles and a lint warning for legacy articles from v1.0.0 wikis. Cleanup agents should fix frontmatter before proceeding with content edits on new articles. For legacy articles, cleanup agents should treat missing required fields as backlog to fix opportunistically when touching the article for other reasons, not as a hard blocker. See `## Migration from v1.0.0` for the full backward-compatibility policy.

### Linking

Use `[[wikilinks]]` between articles. **Obsidian resolves wikilinks by filename, not by the frontmatter `title:` field.** The `title:` field is for display only. To display a human-readable title while linking reliably, use the alias-pipe syntax:

`[[filename_stem|Human Readable Title]]`

Examples:

- `[[cha_baek_dong|차백동 (Cha Baek-dong)]]`
- `[[isd_2027|2027 ISD (필드환경 피지컬 AI 핵심기술 개발)]]`
- `[[joo_hunpyo|주훈표 박사]]`

The `wiki rebuild-index` command must generate index entries in this form. Writing `[[차백동 (Cha Baek-dong)]]` directly, title only, creates a new empty note when clicked in Obsidian unless an exact alias matches.

#### Resolution test

Before declaring an index built, verify that every wikilink resolves by either filename or alias. Use this logic:

```python
# Pseudocode
for target in wikilinks_in_index:
    if target not in filename_stems:
        if target not in known_aliases:
            FAIL(f"[[{target}]] will create empty note in Obsidian")
```

If any wikilink fails, the index generator has a bug. Fix the generator, not the articles.

### Filename Convention (MANDATORY)

Article filenames must be ASCII snake_case:

- lowercase only
- underscores between words, no spaces, no hyphens, no camelCase
- no parentheses, no quotation marks, no colons, no other special characters
- no Korean, Japanese, or Chinese characters
- no leading numbers, for example `01_intro.md` is discouraged; use `intro.md`
- `.md` extension only

Keep human-readable titles, including Korean, parentheticals, and full names, in the `title:` and `aliases:` frontmatter fields only. The filename is an identifier, not a display name.

| BAD filename | GOOD filename | GOOD title, in frontmatter |
|---|---|---|
| `차백동 (Cha Baek-dong).md` | `cha_baek_dong.md` | `차백동 (Cha Baek-dong)` |
| `2027 ISD.md` | `isd_2027.md` | `2027 ISD (필드환경 피지컬 AI 핵심기술 개발)` |
| `Dr. Joo Hun-pyo.md` | `joo_hunpyo.md` | `주훈표 박사` |

### Why this matters

1. **Obsidian wikilink resolution**: filenames are the primary resolution target. Mismatches cause broken links.
2. **Windows path limits**: Unicode filenames hit long-path issues sooner and can trigger unpredictable failures.
3. **Git diff and URL portability**: ASCII filenames are safe in URLs, git logs, shell commands, and cross-platform tooling.
4. **Scripting**: helper scripts using `path.stem` get predictable identifiers.

### Citation Discipline (MANDATORY)

Every claim in every article must trace back to a raw entry ID. Use both forms of citation for dual traceability.

**Canonical source and drift prevention.** The `sources:` frontmatter field is the canonical, machine-readable record. The body `## References` section is a human-readable restatement with context and must not diverge from `sources:`. When the two forms conflict, `sources:` wins. Ideally, `## References` is generated or templated from `sources:` plus cached entry metadata rather than hand-maintained, so the two forms cannot drift. If you must edit them manually, edit `sources:` first and then regenerate or re-sync the body `## References` section to match.

#### 1. Frontmatter `sources:` field, structured

```yaml
sources:
  - a4da93615018
  - e6773219ff38
  - 3df8f26954fe
```

This form is machine-readable and enables automated coverage checks.

#### 2. Body `## References` section, human-readable

```markdown
## References

- Entry ID: a4da93615018 - 2024-03-15 project kickoff meeting
- Entry ID: e6773219ff38 - follow-up decision memo, key constraint X
- Entry ID: 3df8f26954fe - technical feasibility analysis
```

This form provides context, why the entry was cited, and enables human reviewers to trace claims.

#### Entry ID format

Exactly **12 hexadecimal characters**, for example `a4da93615018`, generated by the ingest script as the first 12 characters of a stable hash of the entry's source relative path. Never invent IDs. They come from `raw/entries/{date}_{slug}_{id}.md` filenames.

#### Coverage requirement

**Every raw entry in your batch must appear in at least one article's citations before you declare the batch done.** Use the provided coverage check script:

```bash
python scripts/check_coverage.py
```

This scans both frontmatter `sources:` and body text for 12-hex IDs, and reports any entries not yet cited. If coverage is below 100%, launch a `wiki remediate` pass.

#### When in doubt

If you synthesize content from 10 entries into one paragraph, cite all 10 IDs in that article's References section. Over-citation is safe. Under-citation is a bug.

### Aliases Discipline

Every article's frontmatter must populate the `aliases:` field with at least:

1. **The filename stem**, for example `cha_baek_dong`, which enables `[[cha_baek_dong]]`
2. **The plain title without parentheticals**, for example `차백동` and `Cha Baek-dong`
3. **Any alternative names** used in raw entries, such as `차 박사`, `Dr. Cha`, `차선임`
4. **Shortened forms** of long titles, such as `ISD 2027` for `2027 ISD (필드환경 피지컬 AI 핵심기술 개발)`

Example:

```yaml
---
title: "차백동 (Cha Baek-dong)"
aliases:
  - cha_baek_dong
  - 차백동
  - Cha Baek-dong
  - 차백동 (Cha Baek-dong)
  - 차 박사
  - 차선임
---
```

With this alias set, all of the following wikilinks resolve to the same file:

- `[[cha_baek_dong]]`
- `[[차백동]]`
- `[[Cha Baek-dong]]`
- `[[차백동 (Cha Baek-dong)]]`
- `[[차 박사]]`

#### Why this matters beyond rebuild-index

When an agent in one batch writes `[[차백동]]` while another batch owns the canonical article, the wikilink still resolves correctly as long as the canonical article populated aliases well. This is how cross-batch linking works without centralized orchestration.

#### Alias collision

If two articles share an alias, Obsidian may pick one non-deterministically. The cleanup phase should detect alias collisions via `consolidate_analyze.py` and either merge articles or disambiguate aliases.

### Narrative Coherence

Every article must have a point. Not "here are 4 times X appeared" but "X represented Y in the subject's life." A reader should finish feeling they understand the significance.

### Structure by Type

| Type | Structure |
|------|-----------|
| person | By role or relationship phase |
| place | By what happened there and what it meant |
| project | By conception, development, and outcome |
| event | What happened, brief, why it mattered, bulk, consequences |
| philosophy | The thesis, how it developed, where it succeeded or failed |
| pattern | The trigger, the cycle, attempts to break it |
| transition | What ended, the drift, what emerged |
| decision | The situation, the options, the reasoning, the choice |
| era | The setting, the project, the team, the emotional tenor |

### Quote Discipline

Maximum 2 direct quotes per article. Pick the line that hits hardest.

### Length Targets

| Type | Lines |
|------|-------|

| Person, 3 or more references | 40-80 |

| Company | 25-50 |
| Philosophy, pattern, relationship | 40-80 |

| Decision or transition | 40-70 |
| Experiment or idea | 25-45 |
